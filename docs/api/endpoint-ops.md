# API: operational routes

> The routes nobody designs and everybody depends on. They have no parent feature: they belong to
> the process, not to the product. **Status `draft`: none of it is built.**

## Routes — all of them, no exceptions

| Method and path | Service | Auth tier | In a generated schema? | Purpose |
|---|---|---|---|---|
| `GET /health/startup` | xyk-server | open to the cluster | n/a | a latch: has the migration run and the engine bound? |
| `GET /health/ready` | xyk-server | open to the cluster | n/a | dependency checks; flips to not-ready **first** during shutdown |
| `GET /health/live` | xyk-server | open to the cluster | n/a | the process is not wedged |
| `GET /version` | xyk-server | open to the cluster | n/a | version, commit, build time — generated source |

**Three probes, not one route answering three questions.** Wiring all three to the same handler is
the usual shortcut and it breaks the rollout: a readiness failure then restarts the pod instead of
taking it out of the load balancer.

## Handlers (code anchors)

| Route | Handler |
|---|---|
| all three probes | `server/src/commonMain/kotlin/io/github/youndie/xyk/Application.kt` — `installKoreProbes` |
| the checks behind readiness | `server/src/commonMain/kotlin/io/github/youndie/xyk/health/Probes.kt` |
| `/version` | generated by `io.github.youndie.kore.build` into `commonMain` |
| the chart's probe paths | `charts/xyk/templates/deployment.yaml` |

## What readiness actually checks

Readiness that answers `UP` because nothing was checked is worse than no probe. The registered
checks are:

| Check | Fails when |
|---|---|
| database | a trivial query does not return, or the file is not writable |
| journal size | `walBytes` above the configured ceiling — the disk guard that `page_count * page_size` cannot see |
| delivery workers | no tick completed within N poll intervals; the worker swallows its own exceptions and keeps polling, so silence is the only symptom |

`HealthRegistry.start(scope)` has to be called by us — nothing calls it automatically, and without
it every check reads `UNKNOWN` forever, which looks exactly like a broken dependency
([research §1.10](../research/research-architecture.md)).

## The response of `/health/ready`

Shape from kore, plus our own fields; `walBytes` is ours and carries no default, because a
serializer configured with `encodeDefaults = false` drops a zero and a reader cannot tell an absent
key from "the journal is empty".
